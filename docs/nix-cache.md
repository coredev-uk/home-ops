# Nix cache

`kubernetes/apps/nix-cache` serves an [Attic](https://github.com/zhaofengli/attic) binary cache at `https://attic.hera.ac/coredev` (public through envoy-external: reading needs no token) for [coredev-uk/nixos](https://github.com/coredev-uk/nixos). That repository's `Hosts` workflow builds its hosts and pushes them there with the `ATTIC_TOKEN` secret:

- `atlas` (system and `paul@atlas`, and athena's the same way) on every pull request and push to `main`, on the `nixos-runner` runners (`kubernetes/apps/actions-runner-system/actions-runner-controller/runners/nixos`): one job at a time, each in its own Kata VM, with a Nix store that persists between jobs. They reach Attic at envoy-external directly.
- `poseidon` (nix-darwin) weekly and on demand, and when its system derivation differs from the base's (a flake-update pull request, or a push to `main`; `plan` in the `Hosts` workflow evaluates both), on GitHub's macOS runners, which join the tailnet (`oracle/headscale`, `tag:ci`, allowed only envoy-external's 443) to push. Otherwise its check passes without building, so an update to an input poseidon doesn't use never waits on a macOS runner.

Both skip targets the cache already has (`nix-fast-build --skip-cached`), push each target that built with its runtime closure (`attic push`), and on `main` record each target's store path as a `nix-cache/<target>` commit status. The cache's upstream keys are cache.nixos.org's, nix-community's and nix-citizen's, so Attic skips whatever those already sign and holds only what nobody else builds. Pushes never go through Cloudflare, which rejects request bodies over 100 MB. Attic's chunks live on the NAS share `NixCache` (`expanse.internal:/NixCache`); its database is the CNPG cluster `attic-postgres`, whose exporter also publishes the cache's size (`cnpg_nix_cache_*`). Neither is backed up: the cache is refilled by CI, so losing either means recreating the `coredev` cache with its keypair. The cache's signing keypair lives in that database and, for a rebuild, in 1Password as `ATTIC_CACHE_KEYPAIR`. Paths nobody fetched for 30 days are garbage-collected. The Grafana dashboard is _Nix Cache_.

On a pull request each host's job then compares its closures with the base's (the build on `main` that this cache holds): `nix store diff-closures`, which only substitutes from Attic and the upstream caches, and the closure sizes, posted by the `report` job as a comment, so the update pull requests Clarence merges say which packages changed.

A build that runs the runner's VM out of memory is killed by the VM's own kernel, which nothing on the host sees, and a runner pod is deleted before kube-state-metrics notices it failed. So both alerts come from logs, through vmalert on VictoriaLogs (`kubernetes/apps/o11y/victoria-logs/alerts`): `NixosRunnerOomKill` from the `[nixos-runner] OOM:` line that `start.sh` writes as the pod ends (followed by the kernel's `Killed process` lines), and `ActionsRunnerKilled` from ARC's controller logging a runner pod that died of SIGKILL (exit 137) mid-job. When the runner itself is killed, GitHub never gets the job's log; the `Hosts` workflow makes its build processes the OOM killer's first choice (`oom_score_adj` 1000), so the build fails with a log instead.

One-time setup:

- The NAS share `NixCache`, exported over NFS to the cluster like `Media` and `Kopiur`, writable by uid 65534.
- In 1Password item `nix-cache`: `ATTIC_POSTGRES_PASSWORD`, `ATTIC_SERVER_TOKEN_RS256_SECRET_BASE64`, `openssl genrsa -traditional 4096 | base64 -w0` (Attic needs a PKCS#1 key), and `ATTIC_TOKEN`, made as `kubernetes/apps/nix-cache/attic/app/externalsecret.yaml` describes and also set as the `ATTIC_TOKEN` Actions secret on coredev-uk/nixos.
- The cache, with a short-lived token that may create and configure it: `attic cache create --public hera:coredev`, then `attic cache configure hera:coredev --upstream-cache-key-name cache.nixos.org-1 --upstream-cache-key-name nix-community.cachix.org-1 --upstream-cache-key-name nix-citizen.cachix.org-1`. `attic cache info hera:coredev` prints the public key that `hosts/default.nix` in coredev-uk/nixos trusts. To keep that key in a new database, set the new cache's keypair to `ATTIC_CACHE_KEYPAIR` (`update cache set keypair = '…' where name = 'coredev'` in `attic-postgres`).
- The `hyperion-actions-runner` GitHub App installed on coredev-uk/nixos as well as this repository, and `just oracle ci-authkey` for the macOS runners' tailnet key (Actions secret `TS_AUTHKEY`).
- On coredev-uk/nixos, workflows from outside contributors need approval (Settings > Actions > General): a fork's pull request would otherwise run on `nixos-runner`.
